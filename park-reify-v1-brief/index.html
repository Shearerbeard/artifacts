Decision queue

A. Ruled today (2026-08-26) — recorded, awaiting fold into the board

1. P38 ratified — async webhook. The outbound webhook POST becomes a signed notification (response body ignored; 2xx = delivered). The decision returns later through the existing HMAC'd POST /v1/approvals/{decision_id} ingress. Zero new ingress surface. Park + durable resolve + reify then work identically across routes.
2. P39 ratified — V1 includes single-agent park+reify. "The approval record is durable on redis" was never enough: without a single-agent checkpoint the agent's conversation and plan die with the process. P39 builds the minimal run record, the tool-boundary park boundary, and the same ownership transfer the orchestrated path uses.
3. RedisRunStore killed; PgRunStore carded. Redis is never the run-store answer — the reify claim must atomically check Parked + consume the wake reason + transition + fence, which is one predicated UPDATE in Postgres and a multi-key Lua shim in redis. PgRunStore is carded now, parked behind the session-guard merge (its trigger).
4. Release-at-park ruled. The park commit releases the session lease after the CAS commits. The Parked state plus its wake reasons — not a held lease — gate the reify claim. This is session-guard's shape (commit-then-release with the park latch set) and it fixes the wrinkle where a decision landing one minute after a park would otherwise wait out the lease (up to park_timeout after run start).
5. This page is the review desk. One artifact carries the brief and the flows; the copy-rulings block below is the Stage-0 input for the next board-owner session.

/approvals request logic — the webhook HITL flow

Ingress (unchanged by the stack, unchanged by P38): POST /v1/approvals/{decision_id}. With AURA_HITL_WEBHOOK_SECRET set, the body is verified before parsing — X-Aura-Signature-256: sha256=… over "{unix_seconds}.approval-decision:{decision_id}.{raw_body}", ±300s default skew, primary-then-secondary constant-time verify, every pre-verification failure a uniform 401. Success: 204. Unknown id: 404. The handler calls PendingApprovals::resolve, which on the stack is resolve_durable — first-write-wins, record kept, wake reason durable. HMAC is opt-in: with no secret configured the endpoint parses unverified JSON (feature-off by design; the webhook flow below assumes it on).

Egress today (sync webhook route): the gate POSTs ApprovalRequestWire to the configured URL (signed approval-request:{decision_id} when HMAC is on) and holds the round-trip open — the decision arrives as the response body, verified under approval-decision:{decision_id}. This route never parks; the run dies with the process.

Egress after P38 (ratified today): the outbound POST is a notification — same signed body, response ignored, 2xx = delivered. The run parks (same commit path as conversational). The approver service decides whenever it decides and POSTs the ingress. Notification failure does not deny: the park proceeds, the approval stays pending, the P8 reaper is the fail-closed backstop, and an operator can drive the decision_id from logs/events. An optional on_notify_failure = "deny" posture is a Stage 1 ruling.
