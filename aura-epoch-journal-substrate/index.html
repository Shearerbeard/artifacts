Justin's five gaps — disposition

Surfaced on Slack; vetted line-by-line against the Epoch and aura source. All five real; each resolved in grilling.

#Gap (verified)Disposition
J1thread::sleep in LoadDecideAppend retry (strategies/mod.rs:144) blocks a tokio worker.fix in Epoch → tokio::sleep. Priority fix; Tier A doesn't use LDA, but it's Epoch's own TODO.
J2Conflict on start-run ≠ retry blindly — LDA retries conflicts up to 20×, wrong for session fencing.not at LDA seam Conflict belongs to a read-model + SQL session fence queried before commands (future workstream). No blind-retry wrapper around session appends.
J3No per-event sequence from load (only the final version).sidestepped Not bound to Justin's interface; e20's RecordedEvent<E> envelope is the shape — per-event seq comes back in the recorded envelope.
J4No ranged/limited reads (load is an unbounded Vec).split Reification (Tier B): full-Vec load is Epoch-native, no bound needed. Attach-replay (Tier A contract): read(from,to,limit) IS the contract → add a bounded per-stream read to Epoch.
J5Prune counter must survive, or never prune.never prune Event store is append-only & unbounded; prune caches/in-memory only. Dissolves J5 and GH-780's speculative "durable store by TTL" (explicit contract change — see pitfalls).

Code-removal priorities (do these first — they shrink the swap)

#Removal / simplificationWhy it eases the transition
R1Do not wire the in-memory journal/run stores any further.Neither is wired to the runtime yet. Build the SQLite impl as the first wired durable impl — no in-memory→durable migration to unwind.
R2Delete SessionJournal::drain (journal.rs:202).Dead code at PR head (the run task appends itself); docs still misdescribe it. Kill the wrong abstraction before the durable impl has to support it.
R3descoped Keep JournalEntry::Undecodable / JournalItem::Unknown.Codex R2-3: removing them breaks replay pagination across undecodable rows. Only the handling is confined to the storage boundary — not a deletion.
R4Collapse the Redis path (session-store-redis + redis.rs journal/run accessors).Redis is being removed from the product (dead legacy store). Delete rather than port — avoids a dead conversion.
R5Demote InMemoryJournalStore/InMemoryRunStore → test-only, in order.Only after the SQLite impl + the RuntimeStores bridge rewire the production constructors (RuntimeStores::in_memory(), file-backend accessors). Then delete the "bounds itself" eviction logic a durable store makes irrelevant.
R6No raw-SQL-over-Epoch-schema in aura.All store logic (append, bounded read, tolerant read, the append_and_finish composite) lives in Epoch — the conversion stays one-sided.

Pitfalls

#PitfallMitigation / status
P1A journal append failure cancels the run (task.rs:386) → a SQLite hiccup is user-visible.migrate() installs busy_timeout(5s)+WAL; single-writer discipline; retry SQLITE_BUSY in the adapter — never surface BUSY as Conflict (Conflict fences the session permanently).
P2A Conflict fences the journal forever (OnceLock) → runtime reopens.Impossible under one process + one file + the journal mutex. Two processes on one file is the multi-instance case SQLite explicitly does not serve → SQLite = single-instance only HA waits for Postgres + the fence.
P3RunStore::put failures are only logged → facts can silently diverge from the journal.Add metrics/observability; decide acceptability for V1.
P4seq duplication: payload seq vs row sequence.Agree by construction (§1a): stamp expected.next() before serializing; OCC enforces it. Never trust a client seq.
P5epoch-journal is pre-1.0 (0.1.1) → API churn on the critical path.Pin a git dep or vendor; the e20 merge will move the API further.
P6One tokio-rusqlite actor = write-throughput ceiling across all sessions.Fine for single-instance; measure before assuming it scales.
P7Epoch has no upcasting / event_version → a field rename makes old rows unloadable.aura's Unknown fallbacks mitigate reader-side; do not rename persisted fields casually.
P8Durability makes version-rollback visible (new binary writes variants an old binary can't parse).Envelope-level handled by Unknown; payload-kind-level is a hard error → an aura-schema policy decision (§3), not a store feature.
P9No bridge from SessionStore to RuntimeStores exists (in_memory() is the only constructor).Wiring must be written: hand-build RuntimeStores{runs,journals,skills} from the new SQLite SessionStore.
