2. The architectural drift: designed vs shipped

The card was designed and adversarially reviewed around an allocation ledger; what shipped is a single-writer funnel. The pivot was not improvised — the gate-S spike's verdict was pre-registered (round-1 finding 4), ADR 0010 chartered it as the record's validation gate, and the pivot's consequences were named in advance in both the card and the ADR. When the append threshold broke, the named fallback executed.

What the pivot costs, stated plainly. Writes serialize completely on postgres: exactly one writer at a time, globally — every event transaction, whatever its streams, waits on one lock, so append throughput is bounded by a single writer's commit latency. A wedged writer stalls all writes until its lock_timeout (default 5s) expires, surfacing as the retryable LockTimeout error. ADR 0010 records the trade as taken with eyes open: any future that needs concurrent writers must reopen the record. The spike priced the alternative at 4.4× p99 per append.

The payoff, in the ADR's words: the original failure mode (a committed event landing below an already-advanced cursor and being skipped forever) becomes unrepresentable rather than defended against — no event transaction is ever in flight below a committed value, so a poll can neither skip a committed event nor wait on a value that will never appear. The append path also keeps one transaction (no second commit), and the advisory-lock key space shrinks to a single global key with no acquisition ordering to maintain.

3. The spike verdict that forced it

Run of record: live compose postgres, fixed harness (committed as tests/spike_ledger.rs), complete run 242.8s. Append path: 8 concurrent writers × 10k appends each — 80k samples per path. Batch path: 4 concurrent multi-stream batches over a shared 8-stream pool, 1000 batches per path.

Either threshold broken is a FAIL; the append threshold broke by more than 2×. The cost is real, not a harness artifact: the allocation transaction's second commit fsync roughly quadruples steady-state per-append p50 (3.8ms → 17.3ms), stable across runs. An earlier partial run on cold tables had measured the append ratio at 1.598, but its baseline p99 was 3× slower than the warm run (26ms vs 9ms) while the ledgered path held steady (41.6ms then 39.8ms) — the disagreement was baseline cold-start variance, and the declared run of record governs.

The pivot executed per the consequences pre-named in the record: the card keeps the EventFeed trait, consumer groups, and cursor semantics; the ledger and prefix machinery drop (no ledger table, no reaper, no explicit-sequence rewrite — BIGSERIAL stays, because a single serialized writer makes insert order commit order); the cursor becomes a plain maximum over the committed log; E20 (the runner) is unchanged except ADR 0010's cursor section rewrites; E12 (migrations) is unchanged. Numbers were recorded on the card either way.

4. What shipped (the surface under review)

  • Keyed envelope seam (landed at 094cd1c, the review range's base commit): EventMetadata (opaque string-to-string map) + RecordedEvent + EventBatch over records; bare construction unchanged via a new/from_records split. Persisted by both backends (in-memory root inspection + postgres SQL asserts). Migration 0003 adds the event_metadata JSONB column so no commit drops what the write path carries.
  • EventFeed trait + types: consumer groups (ConsumerGroup, empty string unconstructible), FeedCursor (the ack watermark), DeliveredWatermark (a distinct newtype — the design panel's repair), PollLimit, FeedEntry; validating ack-rejection payloads (Regression / Undelivered carrying NotARegression / AlreadyDelivered rejections, unconstructible in meaningless cross-field forms); spec-suite conformance cases in the E11 pattern, both backends.
  • Both backends' impls: in_memory::feed (root mutex is the writer; log indexes are positions; group progress in the root) and postgres::feed (pool + the epoch_feed_cursors table).
  • Migrations: 0003 (event_metadata JSONB, NOT NULL, '{}' default) and 0004 (epoch_feed_cursors — one row per (category, group) with cursor and delivered watermark, CHECK delivered_to ≥ cursor — plus the outbox intent-key partial unique index). Idempotent; migrate() carries an old-shape database to current alone, pinned by a live test.
  • Property proofs (green at final HEAD): 200 randomized interleavings against a model (in-memory); burn pass-through; complete-delivery-no-latecomer under 8 writers; crash redelivery through a fresh handle (live pg). Two test-authoring errors were caught by the property tests before commit — both fixed in the tests, the implementation unchanged.

5. The review ledger

Every design and gate review on this card was run adversarially by a fresh-context reviewing model (kimi-k3, via the opencode route) against the authoring model (GLM-5.3) — different families, the board's differing-model invariant held throughout. Four further adversarial rounds (2026-08-22) shaped the ledger design before drafting; those live on the card and in ADR 0010's own review ledger.

  1. Design panel at Gate S — FAIL ×2 seats, then confirmation PASS

    Two fresh-context seats over the staged skeleton; both returned FAIL. The shared blocking finding, found independently by both seats: the undelivered-ack conformance case was unsatisfiable by any backend — it asserted delivered_to == FeedCursor::START after the case's own poll had delivered two entries, conflating the ack cursor with the delivery watermark. A second blocking (seat 2): the ack doc called every at-or-below-cursor ack a no-op, making the Regression variant dead code. Five minors across the seats (watermark type, next_position at u64::MAX, payload validation, spec-header portability, a doc contradiction). All repaired at 2b3d67c; a fresh-context confirmation re-review verified every repair against its finding: PASS, zero new findings.

  2. Gate A round 1 — FAIL, 1 blocking + 3 minor

    Blocking: the append funnel wait was unbounded and a lock-wait expiry collapsed into a generic backend error — under the funnel, one wedged writer stalled all appends indefinitely. Repaired at 626ba31: SET LOCAL lock_timeout (default 5s, with_lock_timeout builder) precedes the funnel acquisition; expiry surfaces as the retryable AppendError::LockTimeout(Duration); a live test pins the wedged-funnel outcome storing nothing. Alongside: funnel coverage PASS (every stream_events write fronts WRITER_LOCK), feed contract verified on both backends, migrations correct. The LISTEN/NOTIFY deferral was formally accepted as chartered: the shipped poll is pull-shaped, so the push optimization belongs to a wait-capable poll variant, chartered separately.

  3. Gate A round 2 — 2 minors

    Over the 626ba31 fix diff: the LockTimeout classification covered only the funnel-acquisition statement (the head read, inserts, and commit still misclassified a lock expiry as a generic backend error — reachable via a concurrent migrate() index build blocking an insert past the funnel), and the wedged-funnel test lacked the under_deadline wrapper its batch twin carries. Both repaired at dd7b9ce.

  4. Gate A round 3 — PASS, zero findings

    Over the dd7b9ce delta: diff verified byte-identical to the commit, every post-bound statement classified, pre-bound statements correctly excluded (the GUC is not yet in effect). Gate A passed over the full range 094cd1c..dd7b9ce after three rounds.

  5. Gate M — live proofs green at final HEAD

    Live compose postgres at dd7b9ce: cargo test --features postgres --test e19_feed_properties — 4 passed, 0 failed. The funnel's ordering shadow (8 concurrent writers; one poll delivers every committed row; no latecomer below the acked tip), the durable hole (a rolled-back insert burns a value the cursor passes without blocking), and crash redelivery (a consumer dropped between delivery and ack; a fresh handle receives the same entries in the same order). The wedged-funnel timeout proof ran in the main pg suite (61 passed). Re-scoped to the pivot by the same pre-named consequences: the ledger-era scenarios (reverse-order commits, allocation reorder, orphan reaping) are unconstructible under the funnel and moot with no ledger.

6. Highest-risk changes to weigh

RiskWhat to weigh at Gate U
Complete write serializationThe structural trade: one writer at a time, globally, on postgres. Throughput is bounded by one writer's commit latency; a wedged writer stalls all writes until lock_timeout (default 5s). The retryable LockTimeout is the contract for riding that out — consumers must treat it as retry (ADR 0006 already required this). Any future needing concurrent writers must reopen ADR 0010.
Public surface widenedA new AppendError::LockTimeout(Duration) arm breaks exhaustive matches downstream (the TransactError precedent; the flash-sale spec case retries on it). EventBatch now carries RecordedEvents — bare construction is unchanged via the new/from_records split, but keyed writers construct differently.
Two schema migrations0003 (event_metadata JSONB NOT NULL DEFAULT '{}') and 0004 (epoch_feed_cursors + the outbox intent-key partial unique index, WHERE category = 'saga-outbox'). Both idempotent, applied through E12's versioned-migration mechanism, and proven against an old-shape database — migrate() alone carries a seeded pre-metadata schema to current, pinned by a live test.
