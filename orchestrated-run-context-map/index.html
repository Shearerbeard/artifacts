Key distinction: Session history (prior runs) lands in role:system — it is the system prompt, built once at run start and frozen for the entire run. Within-run iteration context lands in role:user as continuation prompts that grow monotonically. Worker context is role:user per-task and ephemeral. Workers never see session history or the coordinator conversation.

D. Injection Flow — Where Data Lands in the Context Window

The critical asymmetry: session history enters role:system (frozen at run start). Iteration context enters role:user (grows with each iteration). Worker context enters role:user (per-task, ephemeral). Tool output transforms are dynamic injections during execution.

Injection Points

Session history (prior runs) system Run start, once load_session_manifests() → build_session_context() Default 3 manifests

Duplicate call nudge tool When duplicate detected DuplicateCallGuard::transform_output() Appended to the offending tool's output

Scratchpad pointer tool When output > context budget build_file_pointer() replaces inline content File pointer + scratchpad exploration tools
Manifest write (to disk) — End of run write_run_manifest() → persistence.write_manifest() Full run summary for next run's session history

Run Lifecycle

  1. Run init — ExecutionPersistence::new() creates a UUIDv7 run_id; prune_session_runs(max=20) cleans old directories
  2. Coordinator preamble built — base template + skill catalog + vector store context + session history (frozen for entire run)
  3. Iteration 1: Planning — build_planning_wrapper() sends query + worker section + routing tools as role:user
  4. Coordinator responds — calls create_plan, respond_directly, or request_clarification
  5. Workers execute — each worker gets its own context window: worker preamble (role:system) + task prompt (role:user). No session history, no conversation.
  6. Persistence drain — wait for in-flight artifact writes before reading back results
  7. Iteration 1: Continuation — build_continuation_wrapper() sends iteration context (completed/failed/blocked tasks) as role:user. Coordinator conversation grows.
  8. Coordinator decides — respond_directly (final answer), create_plan (re-plan → iteration 2), or request_clarification
  9. Manifest write — write_run_manifest() writes manifest.json to disk. This is what the NEXT run loads as session history.
