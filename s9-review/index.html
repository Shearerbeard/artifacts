What the surface does

Five routes under /p/, server-rendered, on the same axum server as the kid PWA. Vikunja stays the board; this is management only.

RouteWhat it does
GET /pOverview: per-kid chip (In progress / In review / No card), held card title, held-for; watched-board pills
GET+POST /p/boardsWatch list; add by ID or pasted URL, validated live against Vikunja with the three mockup-03 errors inline
POST /p/boards/{id}/removeDrop a watch; 303 back
GET+POST /p/kidsKid list; add by name, 303 straight to the new QR page. A rejected name re-renders with an inline error, never a 500
GET /p/kids/{kid}/qr + POST .../regenerateFull-screen QR (server-rendered SVG, print stylesheet) and rotation; the old token 404s the moment the new one exists

Decisions that carry the risk

The auth seam fails closed and invisibly. ParentAuth is a trait; today's impl reads the tailscale-serve login header against an allowlist. Every parent route authenticates first and answers the shared bare 404 on failure - off the tailnet, the subtree is indistinguishable from nothing. And without CHORE_PARENT_AUTH set, /p/ isn't mounted at all: kid-only deployments are untouched.
Watched boards are a plain postgres table, not an event stream. Operator configuration with no FSM semantics, so no events. The sync service still reads its env config at startup - watch changes take effect on sync restart this card. Hot reload is the recorded gap.
Kid admin reuses the domain commands. Register and RotateToken already existed; KidAdminService in lottery is the operator path that appends them (load-decide-append, ExpectedVersion discipline). crates/api stays a thin HTTP layer.
One server-wide fix fell out of the machinery run. Axum 0.8's nest serves /p but not /p/; NormalizePathLayer::trim_trailing_slash() now wraps the whole router. The kid loop re-ran green as the regression check.

Parked for you at this gate

1. Kid rows carry no registration date. The domain has no registration timestamp, so the "Added Aug 3" meta line renders only when a source exists (the S8 location-line pattern). Nothing to decide unless you want the date - that is a small domain addition.
2. The parent actor is hardcoded to VikunjaUserId 1. The tailnet identity is a login string, not a Vikunja user, so parent-UI actions record parent 1. Coarse but honest; the day two parents act through this surface, the mapping needs to exist.
