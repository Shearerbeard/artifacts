Decisions that carry the risk

The auth seam fails closed - and since your ruling, it also explains itself. ParentAuth is a trait; today's impl reads the tailscale-serve login header against an allowlist. No identity at all still gets the shared bare 404 - off the tailnet, the subtree is indistinguishable from nothing. But a tailnet-identified login that isn't on the list now gets a 403 page naming that login ("Signed in as X. This surface isn't open to this login"), logged server-side. And without CHORE_PARENT_AUTH set, /p/ isn't mounted at all: kid-only deployments are untouched.
Watched boards are a plain postgres table, not an event stream. Operator configuration with no FSM semantics, so no events. The sync service still reads its env config at startup - watch changes take effect on sync restart this card. Hot reload is the recorded gap.
Kid admin reuses the domain commands. Register and RotateToken already existed; KidAdminService in lottery is the operator path that appends them (load-decide-append, ExpectedVersion discipline). crates/api stays a thin HTTP layer.
One server-wide fix fell out of the machinery run. Axum 0.8's nest serves /p but not /p/; NormalizePathLayer::trim_trailing_slash() now wraps the whole router. The kid loop re-ran green as the regression check.

Your rulings, applied

1. Registration date: waits on epoch, not on a payload hack. You asked whether events give it for free - almost: the postgres event rows all carry created_at, but epoch's read API never selects it. Rather than bake a redundant timestamp into the Registered payload, the ask went upstream: Epoch#15. The kids.meta line renders the moment a source exists.
2. Parent actor: fixed. The allowlist entries are now login:vikunja-user-id pairs, and kid commands record the mapped user instead of a hardcoded 1. Two parents can act through the surface and the history tells them apart. The dev fake keeps user 1, so machinery is unchanged.
3. Watch table stays a table. Epoch at our pin has no projection infra, so an event-sourced watch list would be a new aggregate plus a hand-rolled fold - more architecture, not less. Your instinct is logged on S16: once checkpointed projections exist, this decision gets a revisit.
4. Tailnet coupling: there is none to remove. The trait is header-shaped; the tailnet impl is ten lines trusting one stamped header. That IS "tailnet as the network layer so we never write auth" - swapping in OIDC or basic auth later is one impl plus one config variant.
