Findings (both real, both fixed, both frozen as regression legs)

F1 (GLM-5.2): backslash-escaped command names bypassed the static gate

\eval "..." — the brush AST keeps raw word text; my quote-stripping ('/") missed backslash escapes, so \eval never matched the dynamic-primitive list but expanded to eval at runtime. GLM chained it through here-strings (cat <<< "$(\eval ...)") — a second hole: redirect words were never scanned for command substitution — and ran eval'd pipelines (find /bin -exec cat {} \; | wc -l → 236 commands executed). Contained: every read was in-memory infra or in-root; fs/net confinement never broke; the scorer found zero escape signals. But ROE win condition #3 (denied primitive executed with effect) was achieved — a genuine gate bypass.

Fix: gate command-name comparison now strips backslashes as well as quotes; redirect/here-string words are scanned for $(/backticks under the dynamic policy; escaped command names are recorded as an audit feature. Regression legs l20a/l20b/l20c. Re-attack after fix: all denied at the gate.

F2 (K3): .. redirect targets misclassified statically

echo y > /data/out/../../tmp/escape.txt was statically classified as WriteRoot (prefix match on the raw path) and executed. The write landed in the in-memory infra /tmp (no host touch — the runtime decorator had normalization; the gate didn't). A classification-honesty bug, not a host escape. Fix: the gate normalizes paths before classifying (mirroring the fsdec fix from the implementation review). Regression leg l21. Re-attack: denied.

Per the board's REVIEW-TOOLING convention for adversarial review of a standalone prose artifact: numbered findings, explicit verdict, author and reviewer models named, every finding dispositioned.

  • Artifacts under review: KB 06 (modernization lift), 07 (policy ADT), 08 (audit schema + BERT feasibility), 09 (harness design), with 05 (verification) as ground-truth input. Staged at aura-orchestration-mode/.review/rust-bash-design/.

  • Reviewer model: gpt-5.6-sol via codex CLI (codex exec --sandbox read-only), 2026-08-14. Run header confirmed gpt-5.6-sol.
  • VERDICT: FAIL (10 BLOCKING, 1 MINOR) — valid delegation, verdict present.
  • Disposition summary: 11/11 findings accepted (10 fixed in r2 revisions of 07/08/09; 1 partially accepted with reframing). No rejections. The r2 documents supersede r1; this ledger records the delta.

Findings and dispositions

1. BLOCKING — Seatbelt boundary permits undetectable host reads + blanket localhost

Accepted. r1 restricted writes/ports but not reads; a compromised runner or granted native custom command could read host credentials into the writable run dir without tripping a sentinel, and all of 127.0.0.1 exposed unrelated host services. Fix (09 r2): profile now denies file-read outside system libs + clone + the runner's own dir; network pinned to the two mock ports only; the residual is stated instead of implied away.

2. BLOCKING — "Independent" evidence was runner-writable

Accepted. Mock logs, provenance, and scoring inputs sat in the same runner-writable tree; "written by the mock process" established nothing under a shared euid. Fix (09 r2): runs/<id>/monitor/ is Seatbelt-denied to the runner and holds the journal, mock logs, snapshots, and expected provenance; the monitor recomputes binary/scenario/policy hashes itself instead of trusting the runner-reported sidecar.

3. BLOCKING — Sentinels can't prove confinement; L2 accepted a false oracle

Accepted with reframing. A finite hash set detects mutation, not reads — correct. And L2's "deny/error" oracle would have accepted the observed macOS NotFound baseline failure that the crate's own test calls a confinement bug. Fix (09 r2): sentinels reframed as mutation canaries only; read- confinement proven by exact-oracle legs (L2 asserts PermissionDenied specifically); the macOS symlink-test diagnosis (06 #5) gates L2; L16's claim reworded from "leak-safe" to "no detected mutation or unauthorized connection."

4. BLOCKING — Static AST gate bypassable via normal shell semantics

Accepted. eval, source, bash -c, traps, $var command names, command substitution, xargs/find -exec all construct code after the initial AST walk; command-level allow/deny, effect classification, HITL routing, and script identity do not survive them. Compiled fs/net confinement still contains effects, but the policy layer is bypassed. Fix (07 r2): DynamicCodePolicy — Strict mode (the registered-bundle authoring contract) denies scripts containing dynamic-code primitives; ApprovalRequired floors the verdict; Unrestricted only with Open script policy. Runtime per-command interception (dispatch_command patch) explicitly deferred to v2 with the bypass list enumerated. L18 added to prove the gate.

5. BLOCKING — SHA pinning covers only the wrapper

Accepted. A pinned script can source mutable files or bash -c "$payload"; secondary code is neither hashed nor policy-checked. Fix (07 r2): ScriptBundle is transitively content-addressed — entry hash plus a manifest of (hash, vfs path) for every sourced file, resolved and verified through the VFS at gate time; non-literal dynamic loading is denied by Strict mode. L10 now includes a mutated-sourced-file leg.

6. BLOCKING — ADT inexpressiveness and conflicting ownership

Accepted. CommandPolicy as a mutually exclusive enum couldn't express "one custom grant + deny dangerous builtins"; BuiltinsOnly still admitted eval/source/bash; params: Option<None> was a silent grant; two output caps with no precedence. Fix (07 r2): CommandPolicy is now a struct (BuiltinSet with defined deny-wins precedence + separate CustomGrant that can never shadow builtins); ParamsPolicy is a mandatory enum (NoneAllowed/Any/ Exact/OneOf); output ownership split (hard cap in LimitsPolicy, spill threshold ≤ cap in OutputPolicy, validation error otherwise).

7. BLOCKING — HITL layer claimed but absent

Accepted. Effect classes existed but nothing mapped them to approval modes; registered mutating scripts could never require approval; no leg, no audit field. Fix (07 r2): ApprovalPolicy domain maps each EffectClass → ApprovalMode (defaults: read_only Unattended, everything else Required), with per-bundle override; L17 legs added; audit schema v2 carries the approval block including the operator decision.

8. BLOCKING — Test matrix couldn't prove advertised parity

Accepted. L7 missed max_array_elements; spill and DNS-range gaps had no honest leg treatment; L5 overclaimed; L15 tested config selection while implying a containment property. Fix (09 r2): all 11 native limits get legs; wall-clock is its own monitor-enforced leg (L19); a parity-gap table asserts gaps as DOCUMENTED-GAP instead of hiding them; L5's claim narrowed to prefix rejection; L15 reframed as config-selection with the trust axiom stated.

9. BLOCKING — Audit lifecycle impossible for crashes/sink failure

Accepted. A single post-exec record cannot exist when the process aborts (L8) or is killed (L19), and a failed sink cannot hold the record of its own failure (L13). Fix (08 r2 + 09 r2): two-channel audit — runner span record plus a supervisor-owned journal (begin/exit/signal/killed); new outcomes aborted/killed/denied_approval; L13's fail-closed assertion now lives in the journal.

10. BLOCKING — Schema insufficient for the claimed BERT task

Accepted. No operator-decision field (the "free labels" claim was unbacked), no deployment/policy identity, no source reference for rule promotion, no concrete extraction targets, and runtime.net had no emission point at all. Fix (08 r2): schema v2 adds deployment.{id,policy_hash}, policy.approval.decision, source.retained_ref, concrete extraction targets (url_prefix_matched, root labels, ordered operand classes), and renames net rows net_static with the static-only limitation stated. The feasibility verdict is narrowed accordingly: novelty detection + script promotion feasible on v2; the r1 unconditional claim retracted.

11. MINOR — Path-privacy contradiction

Accepted. r1 called raw paths a leak and then put the raw denied path in detail. Fix (08 r2): wire format carries path_class + root label + keyed detail_hash; raw values live only in the secured run-dir copy.

Post-review state

The r2 design is materially stronger in exactly the places the review attacked: evidence integrity, dynamic-code governance, transitive script identity, approval as a first-class domain, and honest gap assertion. Two deferred items are now explicit v2 work: per-command runtime interception (dispatch_command patch) and runtime net-event emission. Gate-1 packet = KB 01–10 with this ledger as the design's review record.

  • Registered scripts are transitively content-addressed bundles, not single hashes (codex #5).

Design inputs (verified facts that shape the ADT)

  • exec() accepts arbitrary composed strings; no registered-script concept (05, 03.1). The script/composed distinction lives in our layer.
  • Parsing is public: static AST walk before execution, no rust-bash patch needed (05, 04.18) — but static analysis only sees the initial AST. eval, source, exec, sh/bash -c, traps, $var command names, command substitution, and ExecCallback subcommands (xargs, find -exec) construct or parse code at runtime (codex #4, cited walker/builtins lines). Compiled VFS/curl confinement still contains effects when these fire; command-level policy and effect classification do not survive them. Hence the strict-static rule below.
  • Custom VirtualCommands are trusted native code bypassing every containment claim (05, 03.2/03.3). They are a policy grant, never a default.
  • NetworkPolicy is fail-closed, prefix-based (05, 01.14).
  • Branch vocabulary to stay compatible with: EffectClass × ApprovalMode, mandatory security keys (D3), fail-closed audit.

Pipeline per exec(source):

  1. Source check — sha256 against ScriptPolicy. Registered: resolve the bundle's sourced files through the VFS, verify each hash (codex #5). Composed: apply ComposedRule.
  2. Static AST walk — parse; walk every simple command: names against CommandPolicy.builtins; redirects against FilesystemPolicy; curl args against NetworkRule; assignments against EnvPolicy; dynamic-code primitives against DynamicCodePolicy (codex #4 — any hit in Strict = Deny).
  3. Effect classification — Mutating if writes; NetworkEgress for curl; ReadOnly otherwise; unclassifiable = Unknown. Force-classified builtin table for known writers (sed -i, tee, cp/mv/rm/mkdir/touch, find -delete).
  4. Approval mapping — ApprovalPolicy[effect] (or bundle override): Required → verdict floors at RequireApproval. Deny > RequireApproval > Allow.
  5. Execute — on Allow (or operator-approved), compile the RustBash instance from policy and exec. Runtime backstops that hold even where static analysis is bypassed: compiled fs confinement, NetworkPolicy, limits, VFS decorator logging.
  6. Audit — emit per schema 08 r2, including the approval decision.

Dry-run: steps 1–4 only — the codex execpolicy check analogue.

08 — Audit Schema + BERT Feasibility (r2, post-codex)

Status: synthesis r2 (orchestrator), revised per codex review ledger 10. Goal (user requirement #2): what plugging an audit layer into rust-bash looks like, and whether the traces are a strong enough schema to train a BERT classifier that suggests policy additions from usage data.

r2 changes (from codex BLOCKING 9–10, MINOR 11)

  • Two-channel audit: runner span record + monitor-owned journal covering begin/abort/kill — a crash can no longer make the record impossible (codex #9).
  • New outcome values aborted / killed / denied_approval (codex #9, #7).
  • Schema gains deployment, policy_hash, operator_decision, source-retention reference, and concrete extraction targets alongside classified values (codex #10).
  • Privacy fix: raw denied paths leave the wire format; the JSONL carries class + keyed hash, raw values live only in the secured run-dir copy (codex #11).
  • Net rows are honestly labeled static-only in v1 (no runtime net event emission point exists without a patch) (codex #10).

Where the audit layer plugs in (r2)

  1. Policy gate (our layer, static): source hash, bundle resolution, AST features, per-domain verdicts, approval mapping, final verdict. No patch.
  2. VFS decorator (our layer, runtime): every fs op logged before delegating (05, 04.9–10). No patch.
  3. Result span (our layer, post-exec): exit code, sizes, duration, error kind. Whole-result only until the ExecutionCounters accessor patch (05, 04.12; 06 #7).
  4. Monitor journal (harness side; in production: the embedding harness's supervisor): spawn/begin, exit status, signal, kill events. This channel is owned by the supervisor, not the executor, so aborts and kills are auditable (codex #9).

Deferred (needs rust-bash patches): per-command timing/counters (dispatch hook), runtime net events (no emission point; builtins resolve before registered commands so we cannot decorate curl — 05, 04.7), env diffs.

BERT-classifier feasibility (r2)

The task, restated precisely: (a) novelty scoring — is this trace normal for this deployment; (b) rule extraction — turn a recurring pattern into a concrete policy addition (promote composed sha → registered bundle; add fs root; add egress prefix; tighten a param allowlist).

  • Extraction targets: retained_ref pins the exact composed source a promotion rule would register; url_prefix_matched and root are the concrete strings an egress/fs rule addition needs (codex #10).

  3. Upstream re-pin (durable fix). Check whether brush 0.4.x added recursion guards (Phase-2 task); if yes, the re-pin partially fixes this class.

Omissions found

  • OverlayFs is not root-confined. lower_path only strips a leading slash and joins the remainder to lower; lower reads, metadata calls, directory reads, and links then use that path directly (src/vfs/overlay.rs:143-195). .. components or symlinks in the lower tree can therefore read outside the configured lower directory.
  • Custom commands are trusted native code. A public VirtualCommand implementation can bypass VFS, NetworkPolicy, host-environment isolation, audit assumptions, and the claim that no host process can be started.
  • Binary output bypasses max_output_size. Aggregate accounting adds only stdout.len() + stderr.len() and omits ExecResult.stdout_bytes (src/interpreter/walker.rs:398-400).
  • ExecCallback weakens aggregate limits. Callback sub-states reset command_count and output_size, and those counters are not folded into the parent (src/interpreter/walker.rs:3367-3373,3435-3441); repeated xargs or find -exec callbacks can exceed intended aggregate budgets.
  • Output limits are post-allocation checkpoints. A single command can construct an oversized result in memory before the next complete-command limit check.
  • Timeout enforcement remains command-dependent. Synchronous native work can overrun until it returns; curl has a separate transport timeout and sleep caps its own duration, but there is no general preemption mechanism.
  • Network URL allowlisting does not constrain resolved addresses. Prefix validation checks URL parsing and serialization, not DNS results or private/link-local IP ranges (src/network.rs:43-56), leaving DNS rebinding and address-range policy to the embedder.
  • No /dev/tcp bypass exists in current source. Independent searches found no /dev/tcp, /dev/udp, std::net, TcpStream, UdpSocket, or generic socket implementation; built-in curl is the sole native network implementation.
  • The curl method label can diverge from the request sent. If policy is configured to allow an unsupported non-body method, send_request falls back to agent.get while retaining the original method string in policy checks and verbose output (src/commands/net.rs:550-594).
  • EXIT traps do not run on all termination paths. Parse errors and propagated interpreter errors return before the trap block (src/api.rs:29-50), which matters if an embedder treats EXIT traps as cleanup or audit hooks.

Appendix A · Security-layer matrix

rust-bash security-layer matrix (AURA governable shell-access facade)

Agent: E3, exploration wave. HEAD: 68d6dbaf7ae059e29cfe1570a421b0e710ec8572. Scope: research only. Maps the 8 AURA security layers onto rust-bash by reading actual code. rust-bash is an in-process, single-threaded bash interpreter over a pluggable VirtualFs; there are no child OS processes (std::process absent from the library — only main.rs:5 uses ExitCode for the CLI).

Claims (numbered)

  1. SHA-pinned registered scripts — ABSENT. Every exec() takes an arbitrary composed command string, parses it, and runs it. There is no distinction between "registered script" and "composed command" anywhere in the code path. All command resolution is by name against builtins, shell functions, cached PATH entries, and registered VirtualCommands (dispatch_command, walker.rs:3594-3692). Nothing hashes or pins a script. A SHA-pinned allowlist would hook at the exec() boundary (api.rs:23) or execute_program (walker.rs:380), hashing the input string and validating argv against an exact-value allowlist before parse/execute. Cost M.

  2. Environment scrubbing — EQUIVALENT-BY-CONSTRUCTION (with a caveat). The library does not read the host environment implicitly. The only std::env::var* call in the whole crate is main.rs:127 (HOME for the CLI history file, outside the library). The default env is hardcoded constants (api.rs:352-377: PATH, USER, HOSTNAME, OSTYPE, SHELL, BASH, TERM, HOME, PWD), not host-derived. Because there is no child process there is no env_clear; the risk AURA's layer-2 guards against (host identity/credentials leaking into a spawned child) simply does not exist here. Caveat: the embedder can inject host env via RustBashBuilder::env (api.rs:283) or exec_with_overrides (api.rs:161-183), so a policy that rejects host-derived variables is still needed if the facade is fed host state. Cost S.

  3. Network egress policy — PARTIAL. A NetworkPolicy exists (network.rs:12-70) with fail-closed default (enabled=false, network.rs:21-32), prefix-matching URL allowlist, method allowlist, redirect cap, response-size cap, and timeout. Enforcement is only inside the curl command (net.rs:246 enforce_policy, called at net.rs:369 and per-redirect net.rs:462). There is no interpreter-level egress gate, so it is only as strong as the set of network-capable commands (currently just curl). A script cannot reach the network through curl when disabled, but any future network command must remember to call enforce_policy. Cost S-M.

  4. Filesystem confinement — PARTIAL (single-root only). ReadWriteFs::with_root (readwrite.rs:60) confines all paths under one canonicalized root; resolve (readwrite.rs:76) normalizes ./.. and canonicalizes the parent, resolve_follow (readwrite.rs:127) closes the final-symlink TOCTOU gap, and canonicalize_existing (readwrite.rs:500) re-checks the existing ancestor. Escape via .. and symlinks is rejected with PermissionDenied and covered by tests (readwrite_tests.rs:198,222,308,469,482,495). However rust-bash has no separate read_roots / write_roots / mask_paths concepts — it is one root for both reads and writes, and there is no "masked path unreadable even inside a root" mechanism. Cost M.

  5. Resource limits + timeout kill — PARTIAL (limits yes, kill-on-timeout no). ExecutionLimits (interpreter/mod.rs:131-161) provides 10 bounds (call depth, command count, loop iterations, execution time, output size, string length, glob results, substitution depth, heredoc size, brace expansion, array elements). check_limits (walker.rs:358-377) is cooperative: it runs between commands and returns LimitExceeded/Timeout errors. There is no process-group kill and no RLIMIT_CORE (no child processes; RLIMIT/libc/nix absent). The timeout builtin is explicitly non-preemptive and only checks after completion (utils.rs:1468-1473), so a long-running single command blocks for its full duration. Cost M (limits are cheap; true kill-on-timeout needs a thread + checkpoint strategy and is structurally harder).

  6. Output caps + spill — PARTIAL (cap yes, spill no). max_output_size is enforced in check_limits (walker.rs:366), but exceeding it returns a LimitExceeded error (walker.rs:366-372, propagated by api.rs:40 ?). There is no spill-to-file facility and no 0600 spill file; output is accumulated in memory as String (walker.rs:399-402), so there is no streaming boundary at which to spill. Cost M.

  7. Fail-closed JSONL audit — ABSENT. There is no audit, structured-log, or JSONL facility in the crate. The only trace-like features are bash's xtrace (set -x, emitted to stderr, walker.rs:2190-2250) and verbose, neither of which is a structured, fail-closed sink. No audit record is emitted per execution, and there is no sink whose failure would refuse execution. Cost L (requires a new audit hook at exec() plus a fail-closed sink policy).

  8. HITL tiering — ABSENT. There is no mutating vs read-only effect classification and no approval routing. Commands are homogeneous VirtualCommand impls; nothing tags them by effect class. Cost L (needs a classification layer over registered commands plus routing).

Summary

rust-bash is a strong in-process sandbox foundation but implements only two of the eight AURA layers directly (env scrubbing is satisfied by construction since it never reads host env; resource limits exist). Network egress and filesystem confinement exist but are partial: egress is enforced only inside curl, and filesystem confinement is a single root with no read/write split and no mask_paths. The four governance layers AURA cares most about — pinned-script allowlisting, fail-closed JSONL audit, output spill, and HITL effect-class tiering — are entirely absent and require new mechanisms (audit and tiering are the largest, needing new architecture at the exec() boundary). Because there are no child OS processes, "process-group kill" and RLIMIT_CORE are structurally inapplicable; timeout is cooperative only. The cleanest adaptation seam for all governance layers is the exec()/execute_program boundary, which currently accepts arbitrary composed strings with no allowlist, audit, or effect classification.

Appendix B · Interception surface

Claims (numbered)

  1. The public builder can inject initial files, env, cwd, custom registered commands, execution limits, network policy, and a whole VirtualFs backend. It does not expose pre-exec policy callbacks, audit callbacks, parser hooks, or command-dispatch hooks.
  2. RustBash::exec() is a synchronous whole-script entry point: it resets counters, stores source text, parses the input string, executes the parsed program, then optionally runs an EXIT trap.
  3. The internal execution path is exec() -> interpreter::parse() -> execute_program() -> execute_compound_list() -> execute_and_or_list() -> execute_pipeline() -> execute_command() -> execute_simple_command() -> dispatch_command() for ordinary simple commands.
  4. dispatch_command() is the best single pre-command policy choke point. It sees the expanded command name, expanded argv, effective stdin, current InterpreterState, and extra input FDs before function, builtin, PATH, or registered-command dispatch. It is private, so a wrapper cannot use it without patching rust-bash.
  5. Granularity is per simple command at dispatch_command(), plus per AST command at execute_command(), pipeline-level at execute_pipeline(), and whole-script at public exec().
  6. VirtualCommand provides a stable custom-command interception surface for registered commands. CommandContext exposes VFS, cwd, exported env, typed shell variables, stdin, binary stdin, limits, network policy, an exec callback, and shell opts.
  7. Custom commands can replace entries in state.commands, including default registered commands with the same name, but cannot generally decorate shell builtins or functions through the public API because dispatch_command() tries POSIX special builtins, functions, and regular builtins before registered commands.
  8. ExecCallback is used by commands such as xargs and find -exec to run subcommands. It observes only a command string plus an optional environment override and returns CommandResult; it does not expose AST, argv after expansion, filesystem touches, counters folded back to the parent, or per-subcommand structured events.
  9. The VFS trait is a broad filesystem choke point. A decorating VirtualFs can log reads, writes, appends, removes, mkdirs, readdir, stat/lstat, chmod, utimes, links, canonicalize, copy, rename, and glob operations.
  10. Runtime command file operations appear to be funneled through VirtualFs; grep found direct std::fs usage in the CLI entrypoint, native filesystem backends, and tests, not in normal interpreter command execution. The native ReadWriteFs and OverlayFs intentionally use std::fs behind the trait.
  11. Network enforcement is currently command-specific, not a global socket choke point. The built-in curl command calls enforce_policy() before the first request and before each redirect, then performs HTTP via ureq. There is no generic network trait for decorating all net attempts.
  12. ExecutionCounters currently record command count, call depth, output size, start time, and substitution depth. They reset at every exec() and are stored in InterpreterState, but no public accessor exposes them directly except via the re-exported state type if an embedder is inside the crate or uses future API additions.
  13. Execution is synchronous and in-process. There is no async runtime in the interpreter path. sleep blocks the thread with std::thread::sleep; curl is synchronous through ureq.
  14. max_execution_time is cooperative, not preemptive cancellation. It is checked in check_limits() after command count increments in dispatch_command() and after each complete command in execute_program_with_stdin(). A long-running single command can overrun until it returns or reaches an internal check.
  15. Public Rust exec() does not use catch_unwind. The C FFI wraps create/exec/free/last_error entry points in catch_unwind, but stack overflow is generally aborting or otherwise not reliably recoverable by this layer.
  16. A RustBash instance is designed to be reusable across exec() calls: state persists, counters and should_exit are reset at entry, and exec_with_overrides() restores cwd/env overrides afterward. Some fatal interpreter flags/state may remain observable internally after severe errors because there is no transaction rollback.
  17. InterpreterState is rich internally: it holds VFS, env, cwd, functions, commands, shell/shopt opts, limits, counters, network policy, positional params, traps, aliases, call stack, persistent FDs, process-substitution state, current source text, line number, and more. The field is pub(crate) inside RustBash, so external embedders only see public accessors unless the API is extended.
  18. brush-parser AST access exists through public interpreter::parse(input) -> ast::Program, and ExecResult/InterpreterState are re-exported. However, RustBash::exec() only accepts strings and does not expose the parsed AST or accept an already-parsed program.
  19. Trace richness is enough for useful policy-suggestion training if rust-bash is patched at dispatch/VFS/network sites: command name, argv, source line, cwd, env snapshot, pipeline context, redirects, fs touches, net targets, verdicts, exit codes, output sizes, and limit counters are available or derivable.
  20. Missing or weak ML features include public per-command hooks, per-command timing, public AST event stream, env diffs, function/builtin resolution outcome as structured data, redirect metadata before/after expansion, pipeline topology in public output, normalized net request/response metadata, and resource counters per command rather than per exec().
  21. MCP server mode is an integration point at JSON-RPC tool granularity. It exposes bash, write_file, read_file, and list_directory, but its bash result is text-formatted and truncated, so it is weaker than in-process hooks for audit/ML traces.
  22. FFI is an alternative whole-script integration point. It accepts JSON config for files/env/cwd/limits/network and exposes create/exec/free/version/last_error, but not custom command callbacks, custom VFS backends, policy callbacks, or structured counters.

Summary (<= 200 words)

The strongest policy/audit design is an in-process patch that adds span-scoped hooks around dispatch_command(), plus decorators for VirtualFs and curl network enforcement. The public builder already supports injecting a custom VFS, custom registered commands, limits, and network policy, so filesystem auditing and whole-script policy are feasible without invasive changes. However, per-command allow/deny/approval requires internal walker changes because dispatch_command() and AST execution functions are private and there is no callback bus. VirtualCommand is useful for registered commands and command-specific decoration, but cannot uniformly wrap shell builtins/functions because builtins dispatch first. VFS is the broadest existing audit choke point for file touches. Network is narrower: built-in curl has clear policy checks, but custom commands can bypass them unless constrained externally. The trace surface is rich enough for ML policy suggestions if patched: command/argv/source line, pipeline context, fs paths, network URL/methods, exit codes, durations, and counters are available or derivable. Missing first-class data includes per-command timing, env diffs, structured AST/result events, and public counter/state access.

/// Consumes a nested construct (e.g., `$((...))` or `$[...]`), handling nested delimiters
fn consume_nested_construct(..., mut nesting_count: u32) -> Result<(), TokenizerError> {
    loop {
        let cur_token = self.next_token_until(Some(terminating_char), true)?;
        if let Some(cur_token_value) = cur_token.token {
            if matches!(cur_token_value, Token::Operator(o, _) if o == nesting_open) {
                nesting_count += 1;
            }
        }
        match cur_token.reason {
            TokenEndReason::SpecifiedTerminatingChar => {
                nesting_count -= 1;
                if nesting_count == 0 { break; }
                state.append_char(self.next_char()?.unwrap());
            }
            TokenEndReason::EndOfInput => return Err(TokenizerError::UnterminatedExpansion),
            _ => (),
        }
    }
    state.append_char(self.next_char()?.unwrap());
    Ok(())
}
