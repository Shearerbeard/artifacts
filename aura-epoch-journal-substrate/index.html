What each mechanism contributes — and what it cannot supply alone

The three consequential Aura gaps

Gaps 1–2 need agreed boundaries before a store adapter; gap 3 needs an honest outcome model — PoC0 can report uncertain work without solving full recovery. Each is sourced from the corrected cross-lane evidence.

#GapWhat the evidence showsStatus
1 Accepted input needs a durable canonical record PR #826 returns a run ID after local admission, not after a durable input commit. Started omits supplied history; fact-store failures warn. Existing File/Redis session stores still select memory-backed journals. A persistence adapter cannot recover facts never recorded. blocking
2 Pure reconstruction needs its own caller boundary Session state, user-visible transcript, and next-turn context are separate read models. Partial UI output is not canonical model context. Cold admission does not rebuild previous execution state. Pure reconstruction must not instantiate a runtime that resumes work or performs tool discovery as a side effect. blocking
3 Sequential external effects need an honest outcome model A genuinely dependent B is selected in a later model request that includes A's recorded result — same-response sequential calls do not establish that dependency. If A modifies an external system and the process dies before recording its result, history cannot determine the external outcome alone. OpenCode marks stale calls interrupted; pi-durable uses a committed phase + declared replay policy; Epoch uses stable intent keys + consumer idempotency. None makes arbitrary external effects exactly-once. ambiguous

Smallest justified PoC0

  1. Step 1: One configured single-instance Aura agent and disposable SQLite journal.
  2. Step 2: Commit the agreed accepted input and canonical output facts.
  3. Step 3: Stop/restart and reconstruct the agreed state, transcript, and next-turn context without provider/tool calls.
  4. Step 4: Request a new turn explicitly using that reconstructed context.
  5. Step 5: Report interrupted/uncertain work without implicit effect recovery unless the user approves that additional scope.
Excluded by default: generic saga/outbox/feed · HA · snapshots · visual tooling · backend teardown · retry policy. Approval continuation and interrupted-tool recovery are user decisions, not assumed scope.
