Artifact reference graph

A design for the orchestration run store: every artifact becomes an addressable node, every relationship a typed edge, and a future search tool filters nodes then walks edges. No filename parsing.
As of 2026-10-07 19:17 UTC · design, not shipped · aura orchestration mode
2
storage layers

A flat node table (the search surface) plus an edge table (the graph). Artifact blobs stay flat files where they are today.

9
edge kinds

Typed, directed relations, almost all provenance-backward: an artifact points at what it came from. See the breakdown below.

3
read relations

Ancestor handoff, linked evidence, forced ancestor. Together they are a worker's read closure.

1
hop of visibility

A worker reads its closure, one hop, session-bounded. Observed reads are logged as edges but never widen the closure.

1
mandatory pre_summary

Every node ships a 1-3 sentence summary at write time, so search reads the index first and the blob only on demand.

The nine edge kinds

EdgeFrom → ToWhat it meansServes
produced_inartifact → run / plan / stepThe structural coordinate: which plan and which step produced this artifact. Denormalized onto the node too, so filters never walk the graph.#3
authored_byartifact → coordinator | workerWho wrote it. Attribution without parsing filenames.#1, #3
descends_fromartifact → artifactThe direct handoff: the previous step's output in the chain. Mirrors the plan DAG frontier.#4
citesartifact → artifactEvidence consumed, with a marker for who linked it: declared (named in the step by the coordinator) or surfaced (older evidence the ancestor chose to show). Both are readable by the descendant; the marker keeps the audit trail honest.#2, #4
forced_byartifact → artifactA coordinator-pinned ancestor output injected into the step, beyond the chain. Distinct from descends_from (the natural handoff) and from cites (advisory evidence): forced means the worker must treat it as input.#4
readsartifact → artifactObserved: an artifact the worker actually opened while working. Provenance and usage signal; does not widen visibility.#4, #6
supersedesartifact → artifactRetry or replan replacement across iterations, so search can collapse iter-1 behind iter-2 while keeping both.#3
bundlespointer → artifactsA coordinator write-artifact pointer listing evidence for a step: documentation and pointers become first-class nodes.#1, #2
answered_byrun / plan → artifactThe run's final answer artifact. The one edge that points forward, from structure to its conclusion.#3

The node schema (the search surface)

FieldShapeWhy it exists
idopaque ArtifactId, minted at writeA stable handle decoupled from filenames. The plan: {run_id}:{seq}. Addresses stay valid across retries and renames.
run_id, session_ididsScope. Cross-run reads stay session-bounded, as they are today.
plan_id, iterationids + counterWhich plan produced it. A replan mints a new plan_id, so iterations never collide.
step_idOption<usize>The index into the plan (task_id). None means a coordinator or run-level artifact.
authorCoordinator | Worker(name)Attribution and filtering by who wrote it.
kindCoordinatorNote | Pointer | WorkerResult | ToolOutput | EvidenceBundle | Handoff | FinalAnswerCoarse filter before any text match.
goalOption<String>The step goal, the main prompt that produced this artifact. Searchable without reading the blob.
pre_summaryString, mandatory1-3 sentences written at creation time. The search blurb: results render from this, never from truncated file heads.
tagsVec<Tag>Typed plus free-form tags.
content_ref{ path, hash, size, format }The flat file behind the node. The filename becomes a storage detail, no longer the identity.
promoted_fromOption<{ tool_name, call_idx }>When the node is a promoted tool output, the exact call it came from. A node field, not an edge: a tool call is provenance, not an artifact.
confidenceOption<high | medium | low>Carried from the worker's structured submit.
statusComplete | Partial | FailedLets search skip or flag dead ends, and pair them with their superseding replacement.
created_atISO 8601 timestampOrdering, freshness, retention. The run manifest already carries a timestamp; each node carries its own.

Orchestration plan: six changes, in build order

  1. write_artifact tool (new, coordinator). Args: goal, pre_summary, tags, content, kind, links[]. Writes a node plus blob, emits bundles/cites edges, returns an ArtifactId handle. Covers both coordinator uses: documenting part of a conversation, and building pointer artifacts to pass into steps.
  2. Steps gain goal and evidence. StepInput::LeafTask (types.rs:84) grows goal, evidence, force; flatten_steps (types.rs:97) carries them onto Task (types.rs:316); the create_plan schema follows.
  3. Worker output becomes an indexed node. At submit_result, write the node with produced_in {run, plan, step}, pre_summary set from the worker's summary, and descends_from/cites/forced_by drawn from the step's inputs. The size-conditional promotion in maybe_create_artifact (orchestrator.rs:3463) becomes one unconditional node-write path.
  4. Workers read by relation, not filename. read_artifact (read_artifact.rs:139) takes an ArtifactId and resolves the one-hop closure: ancestor handoff, declared evidence, forced ancestors, session-bounded. A companion list_readable_artifacts shows the closure with pre_summaries before any read.
  5. Pre-summaries feed search. Every node's pre_summary, goal, and tags go to the vector store surface (vector_store.rs:321) with the ArtifactId as document id and the coordinates as metadata. That surface is a logging placeholder today; wiring it is part of this step, not prior art. Lexical filter first; vector ranking second, optional.
  6. The graph is a persisted, queryable index. A per-run index.json (nodes plus edges) rewritten on every write, atomically via temp file and rename so a crash never leaves a torn index, with a get_artifact_graph lookup (by run, or by artifact with a hop bound). The existing RunManifest (persistence.rs:107) becomes a projection of the node store instead of a parallel structure.

This is a design, not shipped code: nothing here exists behind a flag yet. Open at design time: the ArtifactId minting format, a retention policy for observed reads edges (they grow with every worker read), and whether RunManifest keeps its own file or becomes a pure projection. One scope line: A2A task artifacts, the web-server's existing artifact type, are a different concept and are untouched by this graph.
