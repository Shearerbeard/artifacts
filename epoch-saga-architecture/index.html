crash table

Every crash is a redelivery

Crash pointWhat happens on restartWhy it’s safe
Before the batch append (mid-react)Nothing was written; the feed redelivers the same event.Pure react — no partial state exists.
After the append, before cursor ackEvent redelivered; react runs again; batch re-appends duplicate intents.Idempotency keys absorb duplicates — at-least-once is the contract.
Executor: after the Vikunja write, before the done eventIntent redelivered; the HTTP mutation repeats.BoardPort is idempotent + bot-attributed (echo suppression sees it return).
Executor: mutation fails outrightA failed event is appended; policy decides retry or compensation.Compensate, never roll back — Revert already exists.
Writer dies between ledger allocate and insertRow resolves ABORTED; the cursor skips the hole.The ledger’s durable hole marker.
